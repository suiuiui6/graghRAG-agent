## 1. 参赛定位

### 1.1 项目名称

**石化智脑 — 面向石油化工建设的多模态知识图谱智能体**

### 1.2 一句话

上传石化建设文档 → 自动构建领域知识图谱 → 自然语言问答与任务执行，答案精准溯源到原文页码。

### 1.3 痛点叙事

石油化工建设工程中，大量关键知识沉淀在异构文档中（施工方案、设备手册、安全规范、工艺参数表、故障报告等），格式涵盖 PDF/Word/Excel/PPT/CAD 图纸。工程人员查找一个工艺参数平均翻阅 6-8 份文档、耗时 30+ 分钟。关键字搜索无法回答复杂语义查询，通用 LLM 回答存在幻觉且无法溯源。

### 1.4 赛题对标

| 赛题要求 | 本项目对应 |
|----------|-----------|
| 以设备数据、工艺参数、运维日志等多模态数据为基础 | 支持 11 种工业文档格式自动解析 |
| 结合行业知识库 | 自动构建石化建设领域知识图谱，持久化复用 |
| 具备自然语言交互 | Agentic-RAG 问答引擎，多轮对话 |
| 任务执行能力 | 跨文档知识融合、工艺合规审查、故障推理决策 |
| 自主分析与决策 | LangGraph Supervisor Agent 路由规划 + 多路召回 |

## 2. 三大杀手级场景

### 场景一：故障应急决策

压缩机振动异常 → 系统跨文档检索设备手册、历史故障报告、维护记录 → 输出可能原因列表 + 风险等级 + 建议措施，每条溯源到原文。

**演示冲击力**：从"查文档"到"辅助决策"的跨越。

### 场景二：工艺合规审查

上传施工方案 → 系统自动匹配安全规范文档 → 逐条标注不一致项 → 生成整改清单 + 风险等级。

**演示冲击力**：超越被动问答，展示"主动分析"能力。

### 场景三：跨项目经验迁移

"项目A的塔器吊装用了什么方案？项目B能复用吗？有什么差异？"

系统从两个项目的文档中提取同类实体 → 对比 → 标注差异 + 条件限制 + 风险提示。

**演示冲击力**：传统检索完全做不到，展示"知识推理"。

## 3. 技术架构亮点

### 3.1 全链路

```
文档上传 (11种格式)
    │
    ▼ MinerU 多模态解析
结构化内容
    │
    ▼ BridgePipeline (LangExtract + PositionMap)
实体 + 关系 + 溯源坐标
    │
    ▼ KG Builder
知识图谱 (nodes.json + edges.json)
    │
    ▼ 多路索引: Vector (ChromaDB) + KG (NetworkX) + BM25 + Table
检索基底
    │
    ▼ Agentic-RAG (LangGraph Supervisor + 4 Tools)
    │
    ▼ RRF Fusion + Cross-Encoder Rerank
    │
用户 ← 答案 + 溯源 (page_idx + bbox)
```

### 3.2 技术差异化

| 维度 | 普通方案 | 本方案 |
|------|---------|--------|
| 文档格式 | PDF/Word | 11 种格式 + CAD 引用 |
| 检索方式 | 单一向量 | 四路召回 + RRF + Cross-Encoder |
| 知识组织 | 文本片段 | 结构化知识图谱 |
| 溯源精度 | "基于文档" | 精确到页码 + 段落 + 边界框 |
| 交互模式 | 被动问答 | Supervisor Agent 主动规划 |
| 多文档 | 单文档 | 跨文档融合 + 矛盾检测 |
| 任务执行 | 无 | 合规审查 + 故障推理 + 经验迁移 |

### 3.3 数据要素价值链路

```
原始数据 (工程文档) → 数据清洗 (MinerU) → 结构化 (实体/关系/属性)
→ 知识资产 (KG) → 智能应用 (Agentic-RAG) → 业务价值
(秒级决策、经验复用、风险预警)
```
