## 2. M1 问题定义

### 2.1 应用场景或技术问题

面向中文复杂长文档问答，研究如何让 GraphRAG 在回答事实、图表、列表、数值和跨证据问题时，同时满足以下要求：

1. 最终回答能够追溯到真实、实际进入生成上下文的文档证据；
2. 证据不足时拒答，问题带有错误前提时进行有证据的纠正；
3. 检索探索、上下文规模、延迟和 token 成本具有可审计边界；
4. 论文评测与生产主接口使用同一执行链和同一证据面。

这一定义不把“构建企业平台”作为论文问题，也不把基础设施替换本身视为学术贡献。

### 2.2 需求场景说明

- **用户对象**：需要从论文、报告、制度或项目材料中获得可核验回答的知识工作者。
- **输入对象**：包含正文、章节结构、表格、图题、列表和数值关系的中文长文档。
- **输出行为**：回答、拒答或纠错，并返回可定位来源。
- **使用约束**：错误引用、虚假溯源和无边界搜索的代价高于单纯答案不够流畅。
- **论文边界**：优先研究单文档到小规模跨文档场景；不预设企业级高并发、多租户或大规模图数据库是研究前提。

### 2.3 现有痛点清单

| ID | 痛点 | 当前证据状态 | 对论文的影响 |
|---|---|---|---|
| P1 | 结构边、属性推断边和事实关系容易混用 | 已核实 | 多跳可达性不能自动解释为事实推理 |
| P2 | 文档文本到页码/bbox 的字符对齐存在错误映射路径 | 已核实 | “可追溯”核心主张可能失效 |
| P3 | 图表、列表和数值证据的结构保真不一致 | 部分改善 | 必须单列结构化问题和失败桶 |
| P4 | 引用合法性、事实支持性和语义正确性尚未完全分离 | 已核实 | 不能把 node ID 合法写成“零幻觉” |
| P5 | 历史结果与当前生产主接口/代码版本不一致 | 已核实 | 必须重新冻结并重跑，旧数字只能作历史观察 |
| P6 | 当前仅有单篇文档和 50 题主评测面 | 已核实 | 外部有效性不足，不能泛化到所有中文长文档 |
| P7 | baseline、消融、统计区间和人评尚未闭环 | 已核实 | 暂不能证明比较优势或模块贡献 |

### 2.4 评价目标

后续实验至少需要回答四个评价问题：

1. **证据到达性**：目标证据是否进入 `final-context`，而不只是曾在 `path_hits` 或 `pre-rerank` 出现？
2. **回答支持性**：回答中的每个关键结论是否能由引用证据支持，而不仅是引用 ID 存在？
3. **行为可靠性**：对可回答、不可回答和错误前提问题，回答/拒答/纠错是否分类正确？
4. **质量—成本边界**：在相同检索、上下文和生成预算下，完整方案相对简化基线带来什么收益和代价？

建议主结果面：`final-context` 检索质量 + claim-level answer support。  
诊断结果面：`path_hits`、`pre-rerank`、各检索路径贡献、失败桶。  
工程支撑面：延迟、错误率、release gate；不得替代科学主结果。
