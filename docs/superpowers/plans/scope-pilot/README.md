# 限定范围列举问答：小规模强基线验证包 v0.1

项目：graphrag-paper-001。日期：2026-10-07。当前站：M2部分通过；本包为暂定评测资产，不提前宣告M5通过。

## 结论先行

已重建**3份文档、9道题、31个条目**的标准答案草案；其中8道非空集合题、1道范围内无目标项的负例。3份文档对应3个来源家族，但不是抽样总体的3个独立随机样本。

离线实跑表明：在已知正确范围的条件下，B2预算内章节过滤、B3完整章节/图清单读取，都能保留8道非空题的全部31个原文锚点。最大B3上下文为2581 UTF-8字节。**这不是模型正确率、语义支持率、正式token预算或生产GraphRAG效果。**

初步判断：现有证据更支持优先检查范围路由、清单选择与回答约束的工程缺口，而非立即开发新算法。跨文档范围任务具备验证条件，但“失败可推广”和“新方法具有增量”仍未成立。是否仅局部缺陷需现版本B0与强基线的真实生成比较；若简单基线解决，撤销新算法主张。

## 文件与来源

- `gold.yaml`：条目名称/数值/单位/条件/角色/原文anchor及源文件哈希，**单agent草案，待独立复核**。
- `freeze.yaml`：当前脏工作树7个相关代码/锁文件哈希守卫；不是可恢复代码快照，也不是生产模型/配置冻结。
- `gold-locators.json`：源文件中字符区间与行号；字符是Python Unicode索引、右端不含，绝非PDF页码或字节偏移。
- `pilot.py`：只读离线证据准备、范围定位与裁决计分函数；不导入服务、不调用网络、不加载模型、不写文件。
- `test_pilot.py`：9项软件检查；先失败后实现。合成计分fixture仅测软件行为，不能进入实验结果。
- `evidence-run.json`、`execution.log`、`execution-record.yaml`：已执行的证据可达性检查及来源记录。
- `inputs-B2.json`、`inputs-B3.json`：实际原文上下文＋统一prompt，无gold条目/答案，**仅输入，尚无模型回答**。
- `adjudication-template.yaml`：真实回答和人工条目裁决字段；空模板不是结果。

来源：D1为现有中文制氨论文解析文本；D2为仓库中的Attention Is All You Need解析文本；D3为架构规范。D1四题均开发题，Q15/Q16已有失败分析，另外两题为同文档新增探针。D2/D3五题为探索探针，已由本agent选题并读原文，不叫盲测集。D2可能被模型预训练记忆，D3是规范陈述不代表实际实现。没有新文献检索或作者局限创新论证。

标题页、申报书中的个人信息、`.env`及凭据不进入验证包；其他申报表未作为新样本。源文档保留原位，不覆盖旧GT。无外部上传/存证/DOI；全文与标注仅项目内使用，正式公开前需作者审查版权与项目许可，不能从文件可读推断可公开。

## 对照及公平性

| 标记 | 已完成 | 不能声称 |
| --- | --- | --- |
| B0 现生产系统 | 相关代码/锁哈希守卫 | 未调用端点、未建立D2/D3生产doc映射、无现版本回答 |
| B1 离线词项重叠检索 | 单文档字符块、预算内按排名装入 | 不是生产BM25/dense/hybrid复现；不能当论文主基线 |
| B2 强过滤控制 | 在正确范围内分块、预算内不限固定k | 范围来自已解析元数据，属oracle-scope诊断；未证明自动理解query |
| B3 完整范围控制 | 读取完整指定章节；图题用独立正则从全文提取编号目录 | 目录提取仅适用于这类文本，需目录完整性审查；不能保证任意图/任意文档 |

预算统一上限8192 UTF-8字节，仅作离线大小可行性检查。B1/B2为320字符块、240字符步长，对排名候选用满预算；重叠内容按实际字节计入，不把重复块当多条gold。B3超预算直接标BUDGET_EXCEEDED，不静默截断后声称完整。简单基线可增大k，不故意限制其读取短摘要。

B2/B3的范围选择由预先给定的heading元数据/图清单adapter完成，**不是端到端自动范围解析结果**。模型比较须增加自动范围路由版本，并与oracle版本分开；每题换方式才能解决时记录为适配成本，不隐藏人工帮忙。context组装函数不读取gold items，gold只用于验证和事后检查。

正式比较还需冻结：同一模型及版本、temperature/seed、上下文token与输出token上限、语料入库映射、系统prompt、生产特判和有效配置；保存模型真正看到的context与未截断答案。统一prompt仅用于可控回答器比较，生产原生prompt另作B0-native配置，不能偷偷替换后仍称原生产基线。所有路由、索引、抽取及重试成本另记录。

## 计分与分析计划

research_question：在相同模型/资源下，范围约束的列表回答是否仍超出简单完整范围读取的能力？

estimand：同文档配对B0与强基线的条目完整正确集合差异；当前仅能估计诊断性anchor可达性，不能估计回答效果。

sample_unit：文档/来源家族；题目嵌套于文档，多次生成嵌套于题目。当前3文档9题小样本探索，不做显著性或总体效应推断。文档数不因重复输出增加。

主要outcomes：严格条目recall/precision、完整正确集合、条件/角色错绑、范围外混入、错误穷尽断言、负例范围限定正确性。`score_adjudication`仅接收人工完成的claims；不能自动从数值出现判对。重复正确gold只计一次recall；claim级precision允许正确重复条目但另外要求记录重复，完整集合判断按集合；ERROR/TIMEOUT等不算语义零分，而须另报调用失败，必要时全请求有效正确率将失败计入分母。

空集合recall/precision无定义，记null；只有明确正确的范围限定无项陈述且无错误claim才判完整正确。生成失败也记null，并单列status。错误穷尽断言主要检验遗漏，范围外多报另由scope_violations和完整集合捕获。

models_or_tests：本轮无统计假设检验。后续真实回答先做描述性配对表；足够新文档后再按文档聚类的配对不确定性分析，预先指定主对照，不事后筛显著题。

diagnostics/sensitivity：范围oracle与自动路由分开；完整范围能容纳/超预算分层；D2预训练熟悉度单列；标准答案经独立复核，争议未决项不强计；保留无效调用及重复条目。禁止以本包的易定位短列表构造任务来证明领域普遍失败。

execution_status：离线证据可达性EXECUTED_LOCAL；当前B0和任何模型生成/人工答案裁决NOT_EXECUTED。

## 决策规则与下一步

1. B0在现版本已无失败：历史问题归为已修复/版本相关，不把旧失败包装成当前论文主张。
2. B0有失败，自动范围路由＋完整章节/目录读取能解决：优先工程修复；本包不证明新算法必要。
3. 仅oracle能解决而自动范围路由持续失败：问题收窄为范围识别，需新文档而非继续只改摘要关键词。
4. 跨文档、无现成目录、范围超预算时仍失败，且新方法在强基线和成本控制下有稳定增量：才恢复方法贡献讨论。不能从本包短范围成功/失败直接跨越此门槛。

SCI-Skills统计与复现审查影响：标准答案保留“单agent待复核”，重复题不作独立样本；基线用满预算、oracle能力不冒充端到端能力；代码哈希不冒充模型冻结。不增加期刊名单，不删除旧稿。

唯一下一步：先完成独立gold复核，并确定已有本地模型或可核验的作者运行导出路径，再做现版本B0与自动/完整范围强基线的真实生成比较。没有可用执行路径前不调用远程服务，也不继续包装论文优势。
