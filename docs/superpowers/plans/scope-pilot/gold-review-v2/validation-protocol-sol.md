# 生产基线与自动范围路由：前瞻验证设计

2026-10-07；`graphrag-paper-001 / M / M2 / BASELINE-PROTOCOL-20261007`；专家 `sci-skills-statistical-reporting`，契约 1.0。**仅设计，NOT_EXECUTED**。独立 Gold 复核是另一 AI 的源文审查，不是人工 Gold 认证；本方案不接受阶段、不冻结 canonical Gold、不启动 API。

## 范围与输入

依据同目录 `independent-sol-review.md`、`independent-sol-contract.yaml`、`production-readiness-audit.md/json`、`gold-policy-proposal.yaml`（`2.0-proposed`），以及上一层 `gold.yaml`。Gold 复核覆盖 Markdown 九题、31 草拟条目及五处规则冲突；生产材料是代码只读审计，运行进程、索引和 D3 入库状态仍未验证。本轮未直接复核原始 PDF、生产运行或旧 27 回答，不根据回答选择规则。

目标是先回答“现生产路径是否已经正确、错误发生在哪一层”，再回答“通用自动范围解析是否在共同条件下改善有证据的完整回答”。第三个问题“能否成为研究问题”须经过后续整文档/文档族留出验证，不能由当前三文档决定。

## 方案选择

| 选项 | 设计与用途 | 限制 |
|---|---|---|
| A：只回放真实生产 B0 | 九题逐题保留完整证据链，定位检索、生成、修补和 API 截断 | 可以发现工程问题，不能归因自动路由收益 |
| **B：推荐，两轨最小验证** | A 加同题配对的三臂受控矩阵；先在已见三文档诊断，再决定是否采购新留出文档 | 需补齐运行身份、范围规则和调用门禁；诊断结果无泛化推断 |
| C：直接扩展整文档/文档族留出 | B 的门禁完成后，按冻结任务族和新文档抽样框一次性登记留出，再执行 | 更耗资源；当前无需先做大实验或假定复杂算法值得研究 |

推荐 B。先用当前诊断检查排除工程缺陷；仅在最强简单方案仍有重复失败时进入 C。

## 执行门禁

门禁未过时仍可继续离线设计与源文核对，但不产生“生产验证结果”。按以下清单登记状态和证据路径：

1. **规则门禁**：批准版本化 Gold/问法/属性裁决。至少由评估负责人复核源文绑定；冻结后才生成新回答。审查者对条件臂和模型身份尽可能盲化，记录分歧与仲裁，不能用同一模型自评作为唯一裁决。
2. **运行身份门禁**：记录 commit、dirty diff 指纹、运行模块和进程身份、依赖锁/本地模型、模型实际 ID、prompt、生成/检索/后处理配置及请求 JSON 的脱敏指纹。审计文件哈希只证明当时文件，不能代替运行身份；禁止通过导入生产模块触发下载、初始化或隐式网络。
3. **语料门禁**：记录每个索引快照/hash、全文 hash、索引文档 ID 与 D1/D2/D3 的逐一映射、可检索内容和混合语料范围。当前 `document_id` 回显不等于过滤；D3 是 UNKNOWN。缺失或不可访问记录 `CORPUS_UNAVAILABLE/UNKNOWN`，不记模型失败，不自动补导入。需隔离副本时另行批准并标明副本，不冒称原实例。
4. **位置门禁**：每段上下文逐字回对冻结全文；索引 char span 必须验证原文坐标。重组 offset 无法对应时标 `LOCATION_UNVERIFIED`，保存实际文本与来源，不能报已验证引用/范围证据。统一记录 LF 后 Unicode code-point `[start,end)`、行号；UTF-8 字节另列。
5. **隐私/授权门禁**：确认每源文向供应商传输权限，D1 权利、D2 第三方全文限制、D3 内部规范分别处理；不上传额外全文或敏感 frontmatter。用户已有费用“没有上限”的偏好予以保留，不重新要求人民币数值上限；新批次具体端点、模型、输入范围、有限 provider 调用范围仍需另行批准。本轮没有新批次调用授权。
6. **状态/成本门禁**：核清预处理模型调用、缓存命中、rescue/repair/complete/supplement 是否含隐藏调用、原生重试及 provider usage。新测试使用明确的新会话/缓存命名空间或可回滚副本，记录状态；不删除用户数据。先证明本地 embedding 已就绪，不静默下载。健康检查不能代替这些门禁。

## 两轨与受控矩阵

**轨一 B0_NATIVE**：走现有生产 API/生成器全路径，保留实际多路检索、rescue、rerank 选择、prompt、repair/complete/supplement、缓存及原生请求封装。真实运行配置原样登记，包括 `extra_body` 内的 thinking；不先修参数再称原生 B0。逐题保存 evidence trace、请求/响应时间、provider usage、异常与重试。记录实际语料身份和新会话；B0 不具备题级过滤时，照实记录混合库行为。

**轨二 controlled adapter**：输入同一批已冻结题与源快照，运行三臂。该 adapter 不是未修改 B0，不把它命名为 B0。

本波次在调用前选定一个批准的 query/policy 版本，四路径逐题使用完全相同 query 字符串；推荐批准后使用 v2 问法。受控复用的是该同版本 B0 新捕获，不把旧 27 回答或不同问法的上下文拼进新比较。若需另回放旧问法，独立登记波次和调用范围，只报其原规则/敏感性。

受控三臂的源身份须来自答案生成前真实的用户选中文档/界面上下文或其他已验证用户选择记录，不能从 Gold 的 D1/D2/D3 键推断。“论文中……”在混合库中不能自行确定文档；没有真实选择即 `SOURCE_UNRESOLVED`，保留在可用性账本。原生 B0 保持实际混合库范围，仅诊断；给三臂共同加源约束就是受控干预。若 B0 捕获的上下文跨文档，三臂可按同一事前源选择过滤并记录移除段，但原始 B0 证据不改写。不得在旧问题文本中静默加入文档名；增加标题文本要另记 `query_version`，不能称旧题回放。

| 臂 | 上下文取得方式 | 所回答的问题 |
|---|---|---|
| C_NATIVE_CONTEXT | 复用 B0 已捕获的实际检索序列化上下文，仅施加三臂共同的真实源选择约束，不加 scope 路由 | 共同生成条件下，原有检索上下文够不够 |
| C_AUTO_SCOPE | 通用 resolver 由 query 与真实 heading/caption/table 元数据提出 scope，统一 assembler 取范围内文本 | 自动范围识别是否有效，UNRESOLVED 是否诚实 |
| C_ORACLE_SCOPE | 评估方另传已冻结的显式源范围给同一 assembler | 范围已知时的诊断上界；不是自动能力或可部署方案 |

三臂锁定相同模型/版本、请求设置、生成 prompt（范围描述使用同一格式）、输出 schema、temperature/seed 若支持、预处理、后处理和上下文上限。顶层 thinking 等统一设置先确认供应商接受，再冻结；与原生封装差异单独记录。不得把请求格式修正收益归因给 scope。只复用 B0 已捕获的原始 query、实际 context、预处理结果与候选，不再次调用预处理/检索模型，不把答案缓存带入其他臂；缺少必要捕获先标 BLOCKED。AUTO 采用本地规则，无额外 LLM 路由。受控每单元仅一次生成，禁止自动重试；失败保留。三臂顺序在答案前用固定 seed 配对随机化。

统一的是最大预算和组装算法，不假称每臂实际文本量相同。记录实际字符、估计 token、provider 输入/输出 usage、UTF-8 字节；`4 chars≈1 token` 是代码估计，4000 context 上限不自动等于精确 token；API 的 4000 字符输出限制又是另一变量。超出预算时按共同冻结的优先级/截断规则处理并标 `PARTIAL_SCOPE`；不给 ORACLE/AUTO 无上限全文。若效果随上下文长度明显改变，另做登记后的长度匹配敏感性，不能仅凭臂差异归因范围语义。

resolver 的独立输入只允许用户 query 与运行时真实源标题层级/题注/表格结构；不准 Gold qid、item ID、标准答案、人工 scope 或逐题 lookup。通用规则覆盖 section、编号项、图目录、表格集合，区分图和工具表格；审计中“表格＋所有”命中图检测器不能直接复用为正确 resolver。同号多文档、标题重名、边界不明或低置信度输出 `UNRESOLVED`/候选范围及理由；不读 Gold、不秘密转 ORACLE、也不暗中全文救援。若部署要回落原检索，事前另定义 `AUTO_WITH_FALLBACK`，分报 resolved/abstained/fallback，不能并入纯 AUTO 成功。

## 配对样本、评价与统计口径

以**题为配对比较单位，文档/文档族为独立抽样与分组单位**。九题属于三文档，31 条目和未来生成重复均是下层观察，不是独立 n；27 臂回答不是 n=27。当前文档/回答已见，D2 也可能存在预训练记忆，全部仅诊断；禁止 p 值、功效声明、总体准确率推断或三文档 bootstrap 假精确区间。

在答案生成前登记共同可运行配对题集、Gold 分母、排除原因、臂顺序和停止规则。某一源不存在时，所有涉及该源的对应配对从共同可运行集标记可用性缺口；不得按答案好坏删题。超时/已授权资源耗尽/路由 abstain 与缺 corpus 分列；已可运行题的失败保留。先报每题、每文档的差异和错误类型；有预算才对预先选定题重复同设置评估稳定性，重复不增加独立 n。

不使用 recall 单独裁决成功。为每个输出原子 claim 保留原文、value、unit、condition、role、explicit/inferred、source/span 与审查记录，分报：

- **内容正确性**：条目身份和 value/unit/condition/role 各自正确率、完整 tuple 命中、无依据新增/错误绑定；完整性类别和实质 binding 分开。正集合 item recall/precision 是诊断，旧 COST 每规则单独分母。
- **INPUT 支撑**：claim 是否在该臂模型实际收到的上下文中有证据；Gold 中有答案而 INPUT 无证据的记忆式答对，记内容正确但不计“证据支撑成功”。
- **范围支撑**：证据是否位于批准范围；范围外正确事实单列越界。路由正确/过宽/过窄/UNRESOLVED、scope coverage、预算内可见覆盖另列。
- **覆盖与假穷尽**：全部必要条目且实质属性完备才记严格完整；“全部/只有这些/无”等穷尽表述须有完整范围扫描和覆盖证据，否则记 false_exhaustiveness。输出不足但明确说仅部分的与虚假声称完整的分列。
- **引用**：是否存在、是否支持该 claim、是否到正确源/位置，引用位置未核实不当成功。充分有据的答案与未引用的内容正确答案分报。
- **有界否定**：NONE 不用正条目 recall 分母；核验完整指定范围可见、无 optimizer、回答明确限定本节、不导入 Adam。无检索结果或单纯空输出不是否定证据。

主诊断终点为每题 `strict_supported_scope_answer`：内容及必要绑定完整、实际 INPUT 支持、位于目标范围、引用可核实、无虚假穷尽；空集合用上述有界否定替代。各组成项必须同时报告，禁止一个综合分掩盖来源缺失。另保留延迟、调用次数、实际 token/费用与 abstain 率，不为少量问题构造综合排名。

每臂分别裁决 **原始模型输出 → repair/complete/supplement 后全文 → API 可见答案**，记录逐项新增/删改来源。因 API 4000 字符截断失去的尾项归于接口可见性；因后处理补齐的条目不能归于模型原始提取能力；从输入外补入的 claim 仍须标不支持。范围覆盖不足、生成漏项、后处理误改、接口截断各自归因，无法判定时标 UNKNOWN。

若推进新留出，先冻结文档族、合法且可本地使用的抽样框、整文档/整族 split、任务模板、主终点和新 Gold；专家标注不看模型输出，训练/开发不访问留出答案。改问法后有对应新版本；不得把已有三文档移名成 blind holdout。新样本数根据文档间差异和可接受误差另作计划；届时以整文档/族为重采样层或分层模型处理配对，不把条目行当独立样本。本设计不给尚未知的样本规模捏造 power 或 p 值。

## 有限执行账本与复现记录

推荐诊断波次为九题×四路径＝36 个实验单元。**条件性 provider 硬上限 54 次**：每题 native 最多 1 次预处理＋2 次原生生成尝试，controlled 复用预处理、三臂各 1 次且无重试，总计 `9×(1+2+3)=54`。原生重试行为保留并纳入批准计数。这个上界仅在完整调用图证实不存在额外模型调用、且来源/请求设置门禁通过时有效；有额外 rescue/修补/路由调用即 `BLOCKED_CALL_BOUND`，先重新登记更小批次或新的有限上限。模型化 resolver 不是本推荐方案，若将来研究须另列 arm、调用与预算。

运行前批准本批次有限调用范围、逐请求 max input/output token 与超时；保留用户费用无上限的偏好并报告实际费用。计数覆盖预处理、原生重试、内部模型调用和失败计费。禁止将 max_retries=1 误认为一次尝试；禁止只计成功回答或自行重跑失败。每次 provider 发送前扣保留次数，达到次数/时间 cap 立即停止，余题标 `NOT_RUN_RESOURCE_CAP`；未知 provider usage 标 UNKNOWN，不拿估计替代实际。54 是条件性最大调用提案，不是本轮获授权额度，也不是费用估算。

冻结 manifest 至少含 source/index/runtime/prompt/policy/query/adapter hashes、实际配置、模型身份、cache/session 状态、arm 顺序/seed、request body 脱敏记录、上下文精确文本与范围映射、原始响应、各变换阶段、实际 usage/重试/耗时、评判表与分歧。日志不存凭据；旧 artifacts 不覆盖；未来脚本只写新批准目录。本轮仅完成文件读取和方案文件格式核验，没有代码实现、服务导入、网络访问、实际模型调用、统计分析或费用支出。

## 决策与局限

若 B0_NATIVE 在可验证证据下已完整正确，优先局部回归/工程核验，不以弱离线基线创造研究缺口。若失败仅由文档未入库、条件未触发、请求参数、重组 offset 或截断造成，优先修工程问题并另留原版对照。若通用 AUTO 在相关任务上已解决问题，不再为复杂新算法制造需求。若经过最强简单方案、相同预算与预登记整文档/族留出后仍反复出现有据的失败，才列研究候选；这仍不是新颖性证明。

当前不具备原 PDF 核验、人工 Gold 认证、runtime/index 映射及新 API 权限；这些不妨碍设计交付，但限制其执行和论文结论。质量检查确认真实 B0 与 adapter、AUTO 与 ORACLE、新旧题版本、内容与证据、范围与引用、三阶段输出、诊断与留出推断均已分开；执行检查全部为 NOT_EXECUTED。

**唯一下一步：批准版本化 Gold 规则与本验证设计，随后另行准备执行门禁；本轮不启动新 API 实验。**
