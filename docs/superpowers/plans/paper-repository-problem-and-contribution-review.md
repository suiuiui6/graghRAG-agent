## 1. 结论与选题准则

优先问题：**用户要求在指定文档范围内列全某类条目，系统却把局部相关证据当作完整集合，产生遗漏、范围外混入或未经证实的穷尽断言。**

该问题来自真实仓库记录，不是由顶刊 conclusion/limitations 倒推。顶刊局限仅作定位参考，不再是硬限制；仍必须查直接先行工作、排除简单修补可解决的问题。当前证据支持“历史重复症状＋当前局部机制缺口”，尚不支持“当前端到端仍必然失败”“普遍失效率”“方法优于基线”。

暂定研究问题：在等价模型和资源预算下，范围识别与集合覆盖检查能否比普通 top-k、章节过滤和完整范围读取，更可靠地完成范围约束的列举问答？

## 5. 公平对照设计（尚未执行）

gold单位为条目元组：`名称/数值/单位/适用条件/范围/原文span`，而非易漂移的node_id。文档内重复提及同条目去重，图6与同内容文件名不重复算一张图。摘要指标限定摘要，补充正文须明确标记且不计为范围内答案。

| 对照 | 功能与目的 |
| --- | --- |
| B0 原生产GraphRAG | 保留现有图特判、完整列举prompt、已有摘要boost，固定版本 |
| B1 无KG的flat检索 | 同模型、同语料、同生成prompt、同上下文token上限，用于判断图是否必要 |
| B2 简单强基线 | 章节/页/类型metadata过滤＋top-k＋相同完整列举prompt，不能只比弱基线 |
| B3 完整范围读取 | 摘要整体或图目录整体能放入预算时直接读取；不能故意切碎短摘要；无法容纳的范围另分层报告 |
| H 候选方法 | 问题范围解析→范围内结构清单/检索→条目与条件归并→覆盖检查→回答或明确部分回答；尚未实现，不能声称有覆盖证书 |

控制同一模型版本、温度、语料、token上限、生成prompt和重复运行安排；计入范围扫描、索引构建及重试成本。报告实际tokens、延迟、检索次数，并允许简单基线增加k但不突破同一预算。真实相同输入的配对比较优先，改配置则记录差异。

开发题Q15/Q16只用于诊断，不充当独立最终测试。按文档划分开发/测试，覆盖短摘要、长章节、跨页列表、重复值不同条件、范围外相似干扰、缺失/不可解析范围；样本量由pilot方差与可用文档决定，不凭空指定功效。

主要指标：条目级recall/precision、数值条件绑定、范围外混入率、错误穷尽断言率；另报完整正确集合比例、部分回答覆盖、调用失败率与资源成本。双人标注并记录分歧裁决；置信区间按文档聚类，不把同题多次输出当独立文档。

证据未覆盖全部范围时，只能声称“已检索到以下项”，不等同于一定拒答。覆盖检查也会有抽取误差，必须独立测量，不用“零幻觉”或“保证完整”措辞。

## 6. 贡献候选与停止条件

1. **问题/评测贡献候选**：条目完整性与来源范围正确性分开测，纠正“找到相关片段就等于列全”的评价混淆。成为论文贡献还需多文档、可复核标注和直接先行工作核查。
2. **方法贡献候选**：范围约束＋集合覆盖检查，在长范围/预算不足条件下优于强基线。若仅添加关键词、调top-k、过滤metadata或读完整摘要就足够，撤销新算法主张。
3. **实证贡献候选**：解释不同证据表示为何造成遗漏、越界、条件混绑及假穷尽，并给出质量—成本边界。需冻结context轨迹与消融，历史答案不足以归因。

可证伪规则：现版本不能复现且新测试不显示共性→停止该方法选题；简单强基线同等解决→优先工程修复，不包装算法；优势只在开发题/GT漏标中存在→撤销优势；跨文档预算匹配后仍有可靠增量→再进入M3设计。失败结论照样保留，不强用旧稿。

近期/直接文献仍是查重门槛，不因本仓库真实就自动新颖。本轮平台搜索未返回可读取结果，**没有新增文献核验，也不声称已完成该候选的近期查重**。已有近期核验留在 `paper-recent-journal-limitations-review.md` 和 `paper-conflict-calibration-competitor-review.md`，不可直接当作本候选新颖性通过证明。
