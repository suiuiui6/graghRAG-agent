## 1. 推荐方案 B：全览图 + 模块图 + 评测流程图

这是推荐方案，因为系统实现、四阶段证据核算和实验公平性分别回答三个不同读者问题。

### F-M3-01 / 拟定图 1

- **位置**：正文 §3.2“总体框架”或修订后“生产一致的实验执行合同”之后。
- **标题**：生产一致的 GraphRAG 证据链与受约束回答流程。
- **任务**：解释文档证据与问题如何经同一生产接口形成 final-context，再输出回答、拒答或纠错。
- **面板**：
  - 1a：正文、章节、表格、图题、列表和指标等证据对象；
  - 1b：查询预处理、Vector/KG/BM25、条件 Table、融合、可选重排与预算；
  - 1c：final-context 到 answer/refuse/correct 及伴随审计记录。
- **不表达**：性能数值、可靠 bbox/图像理解、模块均已验证或图边均为事实。

### F-M3-02 / 拟定图 2

- **位置**：正文 §3.7“证据损耗与联合评价”第一段之后。
- **标题**：从路径命中到答案结论的四阶段证据损耗核算。
- **任务**：区分 `path_hits → pre-rerank → final-context → answer claims`，说明保留、补入、过滤、截断、去重和无支持 claim。
- **面板**：
  - 2a：四阶段对象和字段；
  - 2b：相邻阶段的 loss/addition event；
  - 2c：claim、citation 与 evidence span 的支持映射。
- **不表达**：未计算的损耗率、citation-ID 存在即语义支持、因果改善。
- **工程门禁**：release gate 只以虚线正交通道显示，不属于四阶段证据链。

### F-M3-03 / 拟定图 3 或补充图 S1

- **位置**：正文 §4.2“指标与证据面”之后，或移至补充材料。
- **标题**：同一生产接口下的预算匹配 baseline 与验证流程。
- **任务**：说明五级 baseline 如何共享 endpoint、冻结输入、生成配置和预算，并输出检索、claim、行为和成本证据。
- **面板**：
  - 3a：source mask 和模块开关矩阵；
  - 3b：commit、索引、问题集、预处理、预算、模型和 prompt 冻结；
  - 3c：互不混写的四类评价输出。
- **不表达**：方法排名、显著性、未实现功能已完成或 legacy API 是 KG-only baseline。

## 2. 备选方案 A：一张三面板组合图

将上述三个读者问题压缩为图 1a–1c：端到端系统、四阶段证据链、baseline 公平性。

- 优点：节省正文图位。
- 缺点：双栏排版可能造成字号、箭头和术语拥挤；也容易让读者把已实现系统、待实现审计层和实验计划误读为同一成熟能力。
- 适用条件：目标期刊正文图数严格受限，且允许较大横跨双栏图。

## 3. 备选方案 C：只保留全览图

只制作 F-M3-01，四阶段 schema 和 baseline 矩阵改用表格或补充材料。

- 优点：制作负担最低、正文紧凑。
- 缺点：本文真正有区别度的证据损耗核算较难被快速理解。

## 4. 素材、生成与边界

- 必需素材：冻结后的 M3 合同、字段级 schema、实际条件分支和目标期刊版式要求。
- 现有 DOCX 图：仅可在后续做结构审查；默认不复用其结果、标签、图标、配色或艺术资产。
- 推荐路线：原创、代码化矢量 SVG，导出 PDF；期刊需要时再导出 PNG/TIFF。
- 当前禁止：图像生成模型、虚构数值、未核验执行路径、渲染或正文插入。
- 结果图：未来性能、消融和成本曲线均为 `RESULT/NOT_READY`，必须等待真实 frozen run 和 Python/R 执行证据。
