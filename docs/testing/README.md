## 测试层次

工程投入优先级：有效行为测试与真实依赖证据 → 固定全生产范围的双指标及安全扫描 → 可信 CI 必需检查与保护分支。编排格式和 goal/Harness 状态不能替代真实执行证据。CI 门禁需实测双指标任一不足、缺报告、报告过期、统计范围变更及测试失败均不能放行；在部署并核验前不得声称已强制执行。本次 2026-10-13 政策调整未修改 CI 或分支保护。

- 单元：验证行为、边界和异常，必须有有效断言；mock 不能用于冒充真实依赖集成验证。
- 集成：后端每个 API 端点须在 backend/tests 下使用真实依赖验证，遵守现有铁律。
- 功能：将需求验收标准逐项关联到实际场景、预期和结果。
- 适应性：按风险选择环境与配置差异、依赖不可用、异常输入、规模变化、升级兼容、恢复能力。不适用项说明依据；应测但不能执行的项目标为阻塞。

## 统计与防规避

测试策略预先列出各子项目第一方生产代码范围，包含未被导入的文件；依赖、环境、生成及构建产物、测试本身不计入生产分母。范围调整须说明理由并独立评审，禁止为达标删除难测代码。按各自原始计数计算两个指标，不允许显示值四舍五入跨过 90%；零分母或缺失测量不自动视为达标。

单一工具的总 fail-under 不能证明两项指标独立达标。校验须读取行、分支各自计数；后续实现工具时需实测“行通过但分支失败”“分支通过但行失败”“指标缺失”“报告陈旧”等负例均拒绝提交。

禁止删弱断言、无理由 skip/xfail、coverage ignore/pragma、缩小统计范围、手工编辑报告、降低阈值、吞失败退出码或绕过检查。reviewer 检查配置变化、断言与关键异常分支。90% 仅为必要条件，不是测试质量保证。

