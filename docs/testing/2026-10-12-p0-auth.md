# P0 认证与资源授权验证（2026-10-12）

## 输入与根因

按本次 P0 修复范围复用既有认证契约，使用 systematic-debugging 与 test-driven-development。原实现缺省无 ADMIN_API_KEY 全放行，sk- 密钥跳过 JWT 后也没有验证托管密钥；只按路径判 scope 允许 read 删除；JWT 缺 sub/exp、refresh 也能成为请求身份。Tenant 信任 header 并回退假 default 组织。

## 实现契约

- 身份缺省 401；显式 AUTH_ALLOW_ANONYMOUS=true 仅非 production 可生成 viewer 匿名身份。
- ADMIN_API_KEY 生成明确 admin 身份；托管 key 必须真实验证，身份绑定 created_by、viewer，不授系统 admin，read 仅允许 GET/HEAD（query POST 特例）。
- JWT 必须有非空 sub 与 exp；refresh 不可作为 access；production 缺安全秘钥拒 JWT 和签发。
- tenant 仅对显式 X-Project-Id 以真实 project/org/member 建立上下文，无 header 不选默认项目。
- resource_access 的 require_principal、is_admin、authorize_resource、authorized_documents、ingest_identity 共用授权。资源 owner 个人资源可读写，租户资源仍需真实成员；成员写需 owner/org_editor/org_admin，旧无归属仅 admin。
- create_resource_guard_middleware 对未改造全局接口仅允许 admin；非 admin 仅允许主流程资源接口与 auth/me/logout。所有 public 为精确路径。
- 本地任意密码登录仅在显式开发匿名配置下允许，production 禁用。
