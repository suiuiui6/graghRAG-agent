# P0 MinerU 目录隔离与无匹配缓存回归

日期：2026-10-12。范围为后端评估第 3、4 项。使用 systematic-debugging、test-driven-development、verification-before-completion；读取根 AGENTS、memory 索引/今日记录及评估文档后执行。未读取 `.env`，所有 Python 测试均设置 `PYTHON_DOTENV_DISABLED=1`，未调用云服务，未操作真实文档。

## 根因与最终契约

- `worker.py` 两种入口以 `task_id[:8]` 构造目录；`ingest_` 固定前缀使不同完整 ID 碰撞。`download_and_extract` 允许已有目录并覆盖解压，因此残留和并发输出可混合。
- 历史缓存只检查文件名并按字典序选目录，没有输入内容哈希和配置版本匹配。显式开启会将其他文档的产物当成本次上传结果。
- 两种入口现使用完整 ID，先校验 `[A-Za-z0-9][A-Za-z0-9_-]{0,127}` 并拒绝 Windows 保留设备名，再接触供应商。
- 下载阶段以 `makedirs(exist_ok=False)` 独占完整任务目录。ZIP 下载/解压位于该目录下唯一 `.working-*` 子目录；成功后同目录 `rename` 发布为 `result` 并返回其路径。其他线程/进程不能复用该任务目录；已有残留在网络调用前被拒绝。
- 失败保留任务目录与未发布暂存内容，禁止同一标识重新下载覆盖；重新发起业务任务须使用新标识。没有自动删除历史资料。
- 无身份匹配缓存完全禁用。`allow_cached_mineru_output` 兼容接收但不生效，旧扫描函数恒返回 `None`；两条上传路径失败则抛出明确错误，提示缓存禁用。
