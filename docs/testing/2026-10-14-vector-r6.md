## 实现与根因

- `generic_filter.py` 按已核 PyO3 bool→i64→f64机制，将超 I64 的可转换有限 Python int 先转 float，再经记录 serializer/parser 派生兼容值；投影标签与列使用派生类型，raw JSON 保持原 int。真正 binary64 溢出仍返回 `invalid_input` 并保留 cause。不是按夹具数值查表。
- `boundary_probe.py` 与 `test_errors.py` 的旧 `2**63` 必拒绝断言与真实原生接受冲突；独立 reviewer 确认后，仅在新 R6 副本替换为接受、原 int 保真、compat 与投影 float 逐 bit 断言，拒绝项改用 `10**400`。旧冻结未改，原失败日志保留。
- `safe_vector_logging.py` 在异常 formatter 前重建 typed 错误事件白名单，code/operation 固定枚举、异常类别 exact class身份、帧为注册 code 身份映射，未知标识固定替代；不格式化异常值。读取 cause/context/traceback 和 MRO 使用原生 descriptor，保留内部对象引用。
- 接续发现 typed subclass 先前被 exact-class 识别遗漏；真实 console/file 红测试复现裸标记泄漏。修复后用真实 MRO 判继承，输出类别仍 exact identity；验证恶意实例属性、元类属性与伪造 `__class__`。重复节点标志为 `cycle_or_shared`，原因链是首次遇见关系的有界摘要，不声称完整异常图或准确区分共享与环。
- 已确认产品策略：NaN/±Inf 查询向量拒绝 `invalid_input`，`table.search` 不执行。list/tuple、3个位置均检查，合法有限向量保留成功回归。
