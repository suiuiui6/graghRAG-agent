# 项目 Agent 协作工作流设计

日期：2026-10-12。状态：用户已确认书面设计，进入文档实施。

2026-10-13 政策更新：用户明确取消项目级请求自动进入 goal；默认 Superpowers＋项目工作流，保留能力边界、独立 MVP、最小回退和代码快照证据检查。本文中历史 Layer 路由描述仅适用于显式选择 goal＋Harness 的运行；当前规则以根 AGENTS.md 与工作流规范为准。此次仅调整治理规则，未部署 CI。

## 目标与边界

将需求、总体设计、详细设计、独立评审、计划、实现、测试、交付与交接组成闭环。AGENTS.md 是所有 AI 工具的公共入口；Superpowers 技能是执行辅助；docs 是有效规范来源；memory 是跨 Agent 的持久化进度与历史；patterns 是经验证的可复用范式。

本次交付为治理文档及目录索引。保留项目七条铁律、维护期 Layer 路由、现有规范路径与用户工作区修改。不重新初始化现有 Git，不批量迁移旧文档，不安装插件，不修改产品代码。覆盖率工具链与 CI 的建设另行立项；文档规则不能被描述为已实现自动阻断。

## 目录及唯一来源

- `AGENTS.md`：项目约束、启动读取顺序、工作流摘要、技能映射、提交门槛、文档导航。
- `docs/index.md`：当前有效规范与历史规范导航。
- `docs/requirements/`：需求、边界、验收标准。
- `docs/design/`：总体方案与详细设计；本设计即存于此处。
- `docs/contracts/`：接口、数据模型和组件契约。
- `docs/plans/`：新增开发计划；现有 `plans/`、`docs/superpowers/plans/` 保持原位，由索引引用。
- `docs/review/`：设计、代码评审与意见闭环记录。
- `docs/testing/`：测试策略、执行结果与证据导航。
- `docs/governance/`：治理文档。
- `docs/archive/`：被替代的文档；历史排障仍遵循现有 `docs/troubleshooting-archive/` 规则。
- `memory/index.md`：当前目标、阶段、分支及工作区状态、权威设计及计划链接、已完成项、阻塞项、下一步、最新验证证据。
- `memory/YYYY-MM-DD.md`：按任务分节记录动作、决策理由、文件、实际命令与结果、遗留项。
- `patterns/index.md` 及主题文件：适用条件、经验证的方法、限制、来源证据。

不复制已有规范形成第二份权威来源。规范改动回流原文档；记忆仅引用。归档文档标注替代文档、日期和原因，保留可追溯链接。

## 阶段与技能映射

使用本环境已安装技能的短名称；支持命名空间的环境可使用 `superpowers:<名称>`。先发现并读取实际技能，不能把名称存在于文档当作已安装或已执行。

| 阶段 | 技能 | 产出与退出条件 |
|---|---|---|
| 启动及接续 | using-superpowers | 读取项目规则、memory、相关规范，检查 Git 状态与工具能力 |
| 需求澄清 | brainstorming | 目标、约束、范围、验收标准；重要未知项已明确 |
| 总体方案设计 | brainstorming | 备选方案与取舍、架构、组件边界、风险 |
| 详细设计 | brainstorming | 接口、数据流、异常、兼容性与测试设计 |
| 独立设计评审 | requesting-code-review 的评审组织方式，按设计检查表适配 | 独立评审者对需求覆盖、契约、风险、可测试性出具记录 |
| 修改设计与复核 | receiving-code-review 的反馈核实方式，按设计意见适配 | 每条意见有接受或拒绝依据、修改和复核结论 |
| 制定开发计划 | writing-plans | 按依赖拆任务，列文件责任、验收与验证命令 |
| 隔离及任务分派 | using-git-worktrees；独立任务适用 dispatching-parallel-agents | 按风险决定隔离，明确各 Agent 文件归属及共享约束 |
| 按计划实现 | subagent-driven-development 或 executing-plans；test-driven-development | 按任务执行，先验证失败再实现，偏离计划记录原因 |
| 代码评审及修改 | requesting-code-review、receiving-code-review | 检查需求、正确性、安全性、契约与测试质量，修改后复审 |
| 单元测试 | test-driven-development、verification-before-completion | 关键行为及边界有有效断言，真实执行且报告完整 |
| 集成及功能测试 | verification-before-completion；UI 场景补充 webapp-testing | 真实依赖集成测试及验收场景通过；不可运行项明确阻塞 |
| 适应性测试 | verification-before-completion；失败时 systematic-debugging | 验证适用的环境配置差异、依赖故障、异常输入、规模、升级兼容和恢复能力 |
| 故障定位与回归 | systematic-debugging、test-driven-development | 根因证据、复现、修复和回归记录闭环 |
| 交付与归档 | verification-before-completion、finishing-a-development-branch | 门槛验证、规范回流、memory 更新、patterns 提炼、交付方式落实 |

Superpowers 没有在本环境提供独立的设计评审、功能测试、适应性测试和归档专用技能；上述明确区分原生技能与适配用法。webapp-testing 为补充技能，不冒称 Superpowers 原生技能。仅加载当前任务适用的技能，避免同时加载整套技能浪费上下文。

普通修复复用已有需求与设计，不重新跑总体方案评审；仍执行定位、修复、独立代码评审、适用测试、提交门槛和交接。重大变更遵守现有 Layer 路由。批准后的计划持续推进，只在需求歧义、架构取舍、外部授权或真实阻塞时提请用户决定。

## 多 Agent 与跨模型交接

保留 planner / coder / reviewer / debugger 角色。总体及详细设计由 planner 主责，coder 实现，reviewer 独立评审，debugger 定位故障。优先使用独立上下文的评审者，可配置 DeepSeek 设计、GLM 评审，但不强制品牌。

交接包包含任务 ID、需求与验收、输入文件及版本、角色与权限、允许修改的文件、输出位置、检查范围、已知风险、验证方法和完成标准。设计者不得自行冒充独立评审者。不可访问指定模型时生成交接包并如实记录未执行状态；不得伪造外部评审。独立任务可并行，依赖任务顺序推进，多个实现 Agent 不同时拥有同一文件。

评审记录包含问题编号、严重程度、依据、处理决定、修改位置、复核结果。未关闭的阻断问题禁止进入下一阶段。非阻断意见保留接受或拒绝理由。

## Git 提交门槛：双覆盖率 90%

建议写入 AGENTS.md 的强制条款如下：

> 每次 Git 提交前，相关可执行子项目的全量第一方生产代码必须分别达到行覆盖率 ≥90% 和分支覆盖率 ≥90%，且全部规定测试通过。跨子项目变更逐个检查，不以汇总平均值掩盖某个子项目不达标。仅统计变更行、仅统计已导入文件或仅挑选部分通过的测试均不能替代全量统计。指标缺失、无有效测量、报告过期或任一指标不足 90%，均视为未通过，禁止提交，也不得通过降低阈值、绕过检查或伪造报告提交。

覆盖范围在测试策略中固定：包括未被测试导入的第一方生产文件；依赖库、虚拟环境、构建输出、生成代码与测试自身不作为生产代码分母。任何范围调整必须有明确理由和独立评审，不能为了达标排除难测业务代码。行覆盖率与分支覆盖率按各自原始计数独立计算，禁止用混合总分代替或用显示四舍五入跨过阈值。

统计须覆盖最终待提交代码。记录时间、工作区或代码快照标识、测试范围、配置、命令、退出码、行与分支原始计数及百分比，保留机器可读报告和日志。测试后代码或统计配置变化则重新运行。历史结果和其他 Agent 自报通过不能作为当前证据。

禁止删弱断言、无理由 skip/xfail、增加 coverage ignore/pragma、缩小 source/include 范围、修改生成报告、吞掉失败退出码来达标。评审者检查测试是否验证行为、正常与异常分支，并核验测试配置和报告；覆盖率达到 90% 不能替代功能正确性和测试质量评审。

纯文档、memory、patterns 提交仍遵守用户要求的提交前双 90% 门槛，复用有效覆盖范围定义，不因没有产品代码变更自动豁免。本设计阶段不创建 Git 提交；覆盖率基础设施缺失或当前项目不达标时记录阻塞，保留未提交文件，不能借流程技能的“提交设计”步骤绕过用户门槛。

Windows 当前治理声明为 `audit-only-windows`。AGENTS.md 约束 AI 行为，不能保证阻止绕过或作假。将来机械化执行需要单独建设可信 CI 双指标校验、受保护分支和禁止绕过策略；本设计不声称已经启用。

## 验收

1. 根 AGENTS.md 可导航到完整闭环，每阶段有技能、责任、产出及退出条件。
2. 新 Agent 从 memory/index.md 可找到当前进度、历史记录、设计、计划、证据和下一步。
3. docs 与 memory、patterns 职责不重叠，历史规范保留唯一来源。
4. 行与分支独立 ≥90% 的门槛、禁止造假、统计范围、证据要求和未达标处理均明确。
5. 没有虚构插件安装、外部模型评审、测试执行、覆盖率结果或自动阻断能力。
6. 现有七条铁律、Layer 路由及用户进行中的修改保留。
